# Summary

Cheng et al. (arXiv 2605.25836, v1 submitted 25 May 2026, marked "Preprint") propose TTPrint,
a two-phase (diverge-then-converge) pipeline for extracting MITRE ATT&CK techniques from CTI
reports, and — more importantly for this base — **contribute two new evaluation resources
built specifically because the existing benchmark, TRAM, is annotation-noisy**: a cleaned
TRAM (**TRAM-Clean**) and a new document-level benchmark (**TTPrint-Bench**, 150 CTI reports,
125 unique techniques). TTPrint reaches **76.48% and 87.39% macro-F1** on the two.

Why this matters to `ttp-attack-mapping-reliability`:

- It is a **third/fourth independent team** on ATT&CK technique mapping (Virginia Tech group;
  no overlap with CTIBench or CyberThreat-Eval).
- It evaluates **2026-era frontier models** — GPT-4o, GPT-4o-mini, **Claude Sonnet 4.6**,
  **Gemini 2.5 Flash**, **Qwen 3 235B**, **DeepSeek v3.2** — which is the population
  open_questions[0] asks about and which no prior source in this base covers.
- It **states its metric aggregation explicitly** (document-level per-report F1, macro-averaged
  over documents) and **states its label granularity explicitly** (parent techniques only).
- It documents **annotation noise in TRAM** and reports **inter-annotator agreement**
  (Cohen's κ = 0.76 on TTPrint-Bench; κ = 0.74 on TRAM-Clean contested cases).

**Read the limitations before using the 76.48%/87.39%: those are TTPrint-the-system's scores,
not bare-LLM scores, and this base's ctr-0001 is precisely about conflating the two.**

# Key claims

1. **METRIC AGGREGATION IS STATED VERBATIM — DOCUMENT-LEVEL SET COMPARISON, MACRO-AVERAGED OVER
   DOCUMENTS.** From Section 4.1 "Evaluation Setup" → "Metrics": *"TTP extraction is a
   multi-label prediction problem: each report may map to multiple techniques, and models must
   identify the complete set. We evaluate at the document level by aggregating predictions
   across the full report and comparing the resulting technique set to the ground truth. Final
   scores are macro-averages over all documents: F1¯=1|D|​∑d∈DF1d"*. This is a **macro average
   over DOCUMENTS**, not the more usual macro average over classes — a distinction that must
   be preserved, because "Macro-F1" in src-0002's Table 1 header (if that is what it means)
   would be a macro over *techniques*. The two are different statistics with the same name.
   **The item-level TP/FP/FN definition is NOT given**: a targeted fetch asking for the set
   intersection formula returned *"the paper only references macro-averaged F1 computed
   per-document without showing the underlying precision/recall calculations."*

2. **LABEL GRANULARITY IS PARENT-TECHNIQUE-ONLY AND IS ENFORCED IN THE PROMPT.** Verbatim from
   the prompt text: *"Output only ATT&CK technique IDs in parent-technique format: TXXXX, no
   child technique like TXXXX.XXX"*, and from the annotation protocol: *"Annotators labeled at
   the sentence level: for each sentence, they assigned zero or more parent-level MITRE ATT&CK
   technique IDs (format: TXXXX)"*. Together with claim 1 this makes the correctness rule
   *effectively* recoverable — a per-document set comparison over parent-level IDs — even
   though the TP/FP/FN algebra is not printed. **The recoverability is an inference from two
   stated facts, not a quoted rule, and must be cited as such.**

3. **THE EXISTING TRAM BENCHMARK IS DOCUMENTED AS ANNOTATION-NOISY, IN BOTH DIRECTIONS, AND
   HUMAN ANNOTATORS ON THE CLEANED VERSION AGREE AT κ ≈ 0.74–0.76.** Verbatim: *"TRAM contains
   a significant number of annotation errors, including both false positives and false
   negatives"*, categorised by the authors as *"False positives (over-annotation)"* and
   *"False negatives (under-annotation)"*. On the new benchmark: *"Each report carries
   sentence-level annotations produced under double-annotation with adjudication by 3 qualified
   annotators, achieving Cohen's κ=0.76"*; and *"For TRAM-Clean, we report the pairwise κ
   between annotators computed over the set of contested cases"*, at κ = 0.74. Sizes:
   TRAM-Clean is *"2,066 sentences with 665 technique labels across 37 unique techniques"*;
   TTPrint-Bench is *"a new document-level benchmark of 150 CTI reports"* that *"covers 125
   unique MITRE ATT&CK techniques"*. **This is the second independent κ in this base for
   ATT&CK labelling (see src-0020's κ=0.68) and the two are mutually corroborating: trained
   human annotators on parent-level ATT&CK techniques land in the 0.68–0.76 band, i.e.
   "substantial" but well short of the near-perfect agreement an exact-ID scoring rule
   implicitly presumes.**

# Limitations

- **THE 76.48% / 87.39% ARE SYSTEM SCORES FOR TTPrint, NOT BARE-LLM SCORES.** TTPrint is a
  multi-stage scaffold — divergent decomposition, deterministic span localisation, convergent
  verification against MITRE definitions. Comparing these to src-0002's 0.6388 or src-0007's
  0.2787 (both closer to single-inference prompting) reproduces **exactly the SYSTEM-vs-MODEL
  confound that ctr-0001 was opened about** for src-0003's LANCE. A future cycle must use the
  paper's per-backbone bare baselines, which were **not captured this cycle**, if it wants a
  model-level comparand. Capturing the multi-backbone table is the obvious next fetch.
- **AUTHOR-BUILT BENCHMARK, AUTHOR-WINNING RESULT.** TTPrint-Bench was created by the team
  whose system tops it. TRAM-Clean is *their* cleaning of someone else's benchmark. The
  "outperforming the leading baseline by 63.5%" figure inherits that.
- **UNREVIEWED PREPRINT AT v1**, `Comments: Preprint`, no journal reference, no DOI beyond
  arXiv's own. Version staleness nil today; must be re-checked.
- **The item-level correctness rule (TP/FP/FN) is not printed** — see claim 1. Per rule (v)
  this rests on a single URL form and is not a confirmed absence.
- **Not commensurable off the shelf with src-0020 either**, despite both being parent-level:
  src-0020 is sentence-level micro-F1 over open-source models, this is document-level
  macro-over-documents F1 over a scaffold. Two parent-level sources is not two comparable
  measurements.
- Neither this source nor src-0020 supplies a **human-analyst accuracy baseline** (both checked
  ABSENT). `ttp-attack-mapping-reliability` open_questions[1] is therefore **advanced but not
  discharged**: the base now has agreement statistics, not an accuracy baseline.
