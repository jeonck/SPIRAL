## Summary

**The first pre-correction ENISA artefact this base has ever held.**

`institutional-incident-real-world-impact` open_questions[2] has named "the archived
v1.1/original PDF" as a route to the 26-of-492 figure since **cycle 12**, without any cycle
locating one in the sixty cycles since. This is that artefact for the Public Administration
report: version 1.1, served from a `/2025-12/` path, superseded by the v1.2 of 09 January
2026 (src-0026) which ENISA describes as "updated to correct some broken links and typos".

It was found **incidentally in a web-search result list**, not by guessing the path. The URL
resolves.

**No equivalent pre-correction artefact for the Threat Landscape 2025 report (src-0025) has
been located, and that is now the binding obstacle on the 26/492 question.**

## Key claims

1. **The count method proposed in open_questions[2] returns NULL, and this is this source's
   main value.** v1.1 has **exactly 149** numbered footnotes — the same as v1.2. The highest
   footnote number is 149 in both, and its text is **identical** in both. Footnotes 1, 2 and
   3 are identical verbatim to v1.2's; footnotes 147 and 148 are recorded below.
   **A revision that edits link targets does not change the footnote count**, so counting is
   structurally incapable of measuring this correction. Any future version comparison must
   be a **URL-by-URL diff** of the 149 entries, not a count.
2. **The Legal Notice and Acknowledgements are word-for-word identical to v1.2's**
   (src-0026), including the clause disclaiming liability for the content of referenced
   external websites. **This is the load-bearing use of this source**: because that
   disclaimer is present in the *pre-correction* version, it is standing boilerplate and
   **must not be read as a response to the incident**.
3. **The non-disclosure predates the correction.** Asked directly, this version returns
   **ABSENT** for any mention of AI, artificial intelligence, generative AI or LLM in
   connection with how the report was produced, and **ABSENT** for any internal revision
   notice, version history or changelog. So the absence of an AI disclosure was not
   introduced *by* the correction either; it was there from the start.

## Limitations of this source

- **This is v1.1, NOT v1.0.** The report was published 6 November 2025 and this file sits at
  a `/2025-12/` path, so **at least one earlier revision preceded it and no v1.0 artefact has
  been located**. Any diff run between src-0027 and src-0026 therefore measures the
  **v1.1→v1.2 step only** — the step ENISA's landing page describes as correcting broken
  links and typos — and **not** the whole distance from first publication. A cycle reporting
  such a diff must say so.
- **The null result was measured on this report, which is not the 492-footnote report.** 149
  is not 492, so the count method remains **untested** on the report src-0004's figure
  actually describes. What is shown is that the method failed on the one ENISA correction
  this base can currently examine end to end.
- Both v1.1 and v1.2 renders self-reported **NOT TRUNCATED**, so the identical-count finding
  is a real null and not a fetch artefact. But it rests on **one render each**, on one URL
  form each, on one date.
- The footnote comparison performed was a **spot check plus a count**, not a full diff: the
  count (149), the highest-numbered entry, and entries 1, 2, 3, 147 and 148 were compared.
  **The remaining ~144 entries have not been compared**, so this source does **not**
  establish that the two versions' footnotes are identical — only that the count and the
  checked entries are. Since ENISA states links *were* edited, some entries almost certainly
  differ; **finding which is exactly the undone work.**
