## Summary

Authors Emanuele Mezzi, Fabio Massacci, and Katja Tuma (arXiv preprint, cs.CR,
2503.23175) present an evaluation methodology for testing state-of-the-art LLMs on
real-size (not toy/snippet) CTI report tasks. They test three LLMs across zero-shot,
few-shot, and fine-tuning paradigms, and explicitly measure two properties beyond raw
accuracy: **consistency** (does the model give the same answer to the same/paraphrased
input across repeated runs) and **confidence calibration** (does the model's stated
confidence track its actual correctness). The central claim of the paper is that this
combination of properties — not just point accuracy — is what makes current LLMs
unsuitable for production CTI use, because inconsistent/overconfident systems degrade
analyst trust and cannot be safely automated without a human in the loop.

## Key claims

1. "LLMs cannot guarantee sufficient performance on real-size reports while also being
   inconsistent and overconfident" — i.e., the failure mode is not purely accuracy but
   a combination of unreliability across repeated queries and miscalibrated confidence,
   evaluated on 350 real-world threat intelligence reports.
2. Few-shot learning and fine-tuning "only partially improve the results," suggesting
   the unreliability is not simply a data/prompting problem that scales away with more
   examples — it persists across all three tested learning paradigms.
3. The paper frames reliability for CTI as a multi-dimensional property (accuracy +
   consistency + calibration), which is a stronger bar than benchmarks that report only
   task accuracy.

## Additional findings (cycle 3)

Full-text retrieval succeeded this cycle via the arXiv HTML render
(https://arxiv.org/html/2503.23175v1), resolving several open questions left from cycle
1's abstract-only summary. Note: extracted via automated HTML-to-summary tooling (a
fast model reading the rendered HTML), not a manual cell-by-cell read of the PDF
tables — treat exact numbers as high-confidence but not independently hand-verified,
the same caveat already applied to src-0002's table data.

**(1) The 3 LLMs tested**: gpt4o (OpenAI), gemini-1.5-pro-latest (Google), and
mistral-large-2 (Mistral). Notably, none of these three overlap with the model lists
used in src-0002 (GPT-4-turbo, GPT-3.5-turbo, Gemini-1.5, LLAMA3-70B, LLAMA3-8B) or
src-0005 — direct cross-paper comparison at the per-model level is not possible with
current evidence.

**(2) Consistency methodology and numbers**: measured via bootstrapped confidence
intervals (CI) across 10 re-prompts per input, rather than a simple "% agreement"
metric.
- Information Extraction: max CI width 0.02 (e.g. Gemini campaign-retrieval
  precision/recall CI [0.73, 0.74]) — comparatively tight/consistent.
- Information Generation: max CI width 0.06 (e.g. Gemini CVE-generation recall CI
  [0.19, 0.25], described in the paper as a "27.27% percentage difference") —
  noticeably less consistent than extraction.

**(3) Calibration numbers (Table 6, ECE / Brier Score, reported for gpt4o)**,
zero-shot → fine-tuned:
- Information Extraction — Campaign: ECE 0.25 → 0.48; BS 0.26 → 0.48.
- Information Extraction — APT: ECE 0.16 → 0.25; BS 0.15 → 0.23.
- Information Extraction — CVE: ECE 0.28 → 0.18; BS 0.32 → 0.21 (the one case where
  fine-tuning improved calibration).
- Information Generation — CVE: ECE 0.15 → 0.91; BS 0.29 → 0.98 (near-total
  miscalibration after fine-tuning).
- Information Generation — Attack vector: ECE 0.47 → 0.87; BS 0.43 → 1.00.
(Higher ECE/BS = worse calibration; 0 = perfect calibration.)

**(4) Zero-shot vs. few-shot vs. fine-tuned, specifically on consistency/calibration
and accuracy** (Table 4 / Table 7 samples, precision/recall, zero-shot → few-shot →
fine-tune):
- Campaign (gpt4o): 0.72/0.72 → 0.72/0.72 → 0.58/0.58.
- Campaign (gemini): 0.77/0.77 → 0.73/0.73 → 0.61/0.61.
- APT (gpt4o): 0.87/0.87 → 0.84/0.84 → 0.68/0.68.
- CVE extraction (mistral): 0.72/0.90 → 0.79/0.91 → 0.71/0.69.
- Info-generation "Labels" (gpt4o): 0.50/0.50 → 0.44/0.44 → 0.44/0.44.
- Info-generation CVE (gpt4o): 0.10/0.06 → 0.08/0.07 → 0.00/0.00 (complete failure
  after fine-tuning).
- The paper additionally reports few-shot reduced APT-extraction performance by 7.87%
  (0.89 → 0.82, gemini/mistral) and fine-tuning caused a 21.84% precision/recall drop
  for APT extraction (gpt4o/mistral); few-shot also worsened CVE-extraction ECE
  (0.28 → 0.35).

**Key sharpening of the original claim**: the abstract says few-shot/fine-tuning "only
partially improve" results. The full-text numbers show this is generous — on several
sub-tasks (APT extraction, CVE generation, attack-vector generation), fine-tuning and
even few-shot prompting made accuracy and/or calibration measurably *worse*, not just
insufficiently better. This is a meaningful refinement, not a contradiction, since the
abstract's claim ("only partially improve") is still directionally consistent with
"sometimes no improvement or regression."
