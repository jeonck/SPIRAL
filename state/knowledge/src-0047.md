# Cybersecurity Detection Classification with Reasoning-enabled LMs (arXiv 2607.28460)

## Why this source was accepted, and what it is NOT

Collected at cycle 134 (a T1 targeting `consistency-calibration-as-failure-mode`) while searching
`open_questions[5]` and `open_questions[11]`.

**IT SATISFIES NEITHER QUESTION AS WRITTEN, AND A SUCCESSOR MUST NOT REPORT THAT IT DOES.**

- **`open_questions[5]` (a second *CTI* source measuring proper-scoring calibration): NO.** Asked
  directly for Expected Calibration Error, Brier score, reliability diagram or log loss, the body
  render returned **ABSENT**. The paper reports precision, recall and accuracy, and operates
  confidence *thresholds* at target precision tiers, but computes **no proper score and no
  calibration metric**. It is also arguably not a CTI task at all — see the task note below.
- **`open_questions[11]` (fine-tuning paired with a proper score): NO**, for the same reason.

**WHAT IT DOES CONTRIBUTE, AND IT IS WORTH THE SLOT.** It is the first source in this base to report
that a **training intervention degrades the token-level confidence signal on a security-operations
task**, and to report what happens operationally when that signal is trusted anyway. It is
security-domain, industry-scale, and it is direct evidence for this issue's core thesis — that
confidence quality is a failure mode distinct from accuracy — in a deployment setting. It is
**qualitative on calibration and quantitative on the operational consequence**, which is the reverse
of the usual shape in this base.

**TASK NOTE, LOAD-BEARING FOR SCOPE.** The task is **SOC alert triage** — binary malicious/benign
classification of Windows endpoint detections — **not** CTI report analysis, IoC extraction from
narrative text, or ATT&CK mapping from reports. It is *security-adjacent to CTI*, in the same way
src-0013 (code security) and src-0042 (vulnerability detection) are. **UNDER THE STANDING CTI
EXCLUSION RULE IT MUST NOT BE COUNTED TOWARD CTI MULTI-SOURCE SUPPORT FOR THIS ISSUE.** The
calibration leg of `consistency-calibration-as-failure-mode` remains **single-source on src-0001**
after this cycle.

**It does, however, bear on `automated-triage-under-refusal`** — the issue that has never been
investigated in 133 cycles and whose sole candidate is effectively single-source on src-0007. A
future T3 on that issue should read this. Cycle 134 entered no candidate there because a T1 does not
restructure issues.

## What the study does

- **Task:** binary triage (malicious vs benign) of real, human-labeled Windows endpoint detections.
- **Scale:** 388,336 train / 59,162 validation / 42,686 test detections, over consecutive 8/2/1 week
  periods (body render). **Note the temporal split** — train, validate and test are disjoint in
  time, which is a stronger design than a random split for this task.
- **Input features (body render):** *"process lineage (command lines, file names, file paths), local
  and global prevalence, MITRE ATT&CK tactic and technique mappings, detection metadata (severity
  and pattern disposition), and free-text analyst context."* ATT&CK mappings are an **input**, not a
  prediction target — do not file this as an ATT&CK-mapping measurement.
- **Models:** Nemotron-3-Nano-30B (the fine-tuned classifier, and the calibrator), Nemotron-3-Super-120B
  (reflection LM), and frontier comparators Claude Haiku 4.5, Claude Sonnet 4.6, Claude Opus 4.6.
  **NO MODEL OVERLAP with src-0001, src-0002, src-0005 or src-0018.** This does not help
  `open_questions[1]`.
- **Training:** chain-of-thought reasoning trained via automated prompt optimization, self-training,
  and reinforcement learning with verifiable rewards.

## Key claims (verbatim-supported)

All three are quoted from the abstract, which was captured **independently from two renders** and
matched word for word.

**KC1 — TRAINING FOR REASONING DEGRADES THE TOKEN-PROBABILITY CONFIDENCE SIGNAL. This is the claim
that earns the source its place.** Verbatim:

> "We find that CoT reasoning also degrades the label-token probabilities that automated triage
> relies on, so we separately train a calibrator that reads the full reasoning trace and estimates
> the probability that the verdict is correct."

**NOTE WHAT THIS IS AND IS NOT.** It is a **directional, unquantified** statement that an
accuracy-improving training intervention **damaged the confidence signal** — the same shape as
src-0001's fine-tuning result and src-0046's coverage collapse, on a third axis and a third domain.
The degradation is **not measured with any calibration metric**; this cycle found no ECE, Brier or
reliability-diagram evidence for it anywhere in the paper. **CITE THE DIRECTION, NEVER A MAGNITUDE.**

**KC2 — THE OPERATIONAL CONSEQUENCE OF AN UNCALIBRATED CONFIDENCE SIGNAL, AND IT IS TOTAL.**
Verbatim:

> "We further show that the trained calibrator is necessary - an untrained confidence judge collapses
> high-confidence recall to zero - and that a finetuned 30B model significantly outperforms frontier
> general-purpose models, motivating targeted training over scale."

**"COLLAPSES HIGH-CONFIDENCE RECALL TO ZERO" IS THE STRONGEST STATEMENT IN THIS BASE ABOUT THE
OPERATIONAL COST OF MISCALIBRATION IN A SECURITY AUTOMATION PIPELINE.** It says that at the
operating point where automation actually acts, an untrained confidence estimate yields *nothing
usable*. Cycle 134 did not locate the supporting table; the claim is quoted from the abstract only.
**DO NOT ATTACH A NUMBER TO "ZERO" BEYOND THE WORD ITSELF, AND DO NOT NAME AN OPERATING POINT.**

**KC3 — headline performance, for context only.** Verbatim:

> "Our system reaches 82.6% test accuracy and, at the high-confidence operating point that governs
> automated triage, improves benign recall by 43.0% and malicious recall by 18.3% over a direct-label
> LLM classifier."

**CITATION HOLD ON KC3's THREE NUMBERS.** 82.6%, 43.0% and 18.3% were captured from the abstract on
both renders and agree, **but no cycle has yet seen the table behind them**, and the two recall
figures are *relative improvements over a baseline this cycle did not characterise*. Use them only
with the baseline named as "a direct-label LLM classifier" and never as absolute recalls.

## Limitations

**Agent findings — the paper's own limitations section was not read this cycle and that is itself a
gap to record:**

1. **NO CALIBRATION METRIC OF ANY KIND** (ABSENT, asked directly). KC1's degradation claim is
   therefore unquantified and unfalsifiable from what is printed.
2. **NO REPEAT-QUERY CONSISTENCY OR RUN-TO-RUN VARIANCE** (ABSENT, asked directly). This source says
   nothing about the consistency half of this issue.
3. **Vendor-authored, proprietary data.** The 388k/59k/43k detection corpus is internal and, on what
   this cycle read, not released. **The result is not independently reproducible.** This is the same
   structural weakness the base already records against other vendor sources.
4. **Not peer-reviewed**; nine days old at time of collection; no citations or replication exist yet.
5. **Single deployment, single OS, single vendor's detection pipeline.** Windows endpoint detections
   from one product's telemetry. Transfer to CTI report tasks is not established and is not claimed.
6. **The abstract's framing conflates two interventions** — CoT training and RL-with-verifiable-rewards
   are applied together, so KC1's attribution of the confidence degradation specifically to "CoT
   reasoning" is the authors' reading of a combined intervention, not an ablation this cycle
   verified.
