## Summary

This paper (arXiv 2506.11325) tackles indicator-of-compromise (IoC) extraction, a
narrower and more mechanical CTI sub-task than TTP mapping or attribution. The authors
built PRISM, described as the first open, fully manually-validated, documented
benchmark dataset of IoCs from threat reports (1,791 indicators from 50 real-world
reports, covering domains, URLs, IPs, and file hashes). They then built LANCE
(LLM-Assisted Notation and Classification Engine), a hybrid system combining
regex-based candidate extraction with LLM-based labeling plus explainable
justifications for human reviewers, and benchmarked it against existing tools
(IoC Searcher, AlienVault OTX, VirusTotal). This is a useful counterpoint to
src-0001/src-0002: it shows that for the narrower, more mechanical IoC-extraction
task (as opposed to open-ended reasoning like attribution or ATT&CK mapping),
LLM-assisted hybrid pipelines can substantially outperform both pure-regex tools and
raw un-augmented LLM labeling — reliability appears to be very task-dependent.

## Key claims

1. LANCE achieved 97.6% overall F1 against the manually-validated PRISM ground truth,
   outperforming IoC Searcher + whitelist (76% F1), AlienVault OTX (72% F1), and
   VirusTotal at detection threshold=1 (86% F1), and stayed above 90% F1 across all
   four indicator types (IPs, domains, URLs, hashes).
2. Human-in-the-loop use of LANCE's LLM-generated justifications reduced junior
   analysts' manual parsing/annotation time by 43% versus a fully manual workflow,
   and downstream models trained on LANCE-labeled data outperformed those trained on
   VirusTotal-labeled data by over 6% F1 — evidence that LLM assistance, when
   constrained to a narrow extraction+explanation role with human validation, can
   raise both speed and downstream data quality rather than just raw accuracy.
3. LANCE's approach generalized across different underlying LLMs (reported ~0.92 F1
   with Gemini, ~0.88 F1 with Llama), suggesting the reliability gain comes from the
   hybrid regex+LLM+human-validation architecture rather than from a single specific
   model.

## Relevant quotes

- PRISM is "the first open, fully manually validated, and well-documented benchmark
  dataset of IoCs from threat reports, consisting of 1,791 indicators extracted from
  50 real-world threat reports."
- LANCE labeled "over 99% of all extracted indicators" versus VirusTotal's 84%
  coverage, and achieved "97.6% overall" F1.

## Limitations of this source

- Content was retrieved via automated HTML summarization of the arXiv HTML render
  (v2), not a full manual read; exact per-type F1 breakdowns and the precise
  regex/LLM task split in the LANCE pipeline should be verified against the full PDF
  before being used to justify a strong resolution in the issue graph.
- The 97.6% F1 figure is against the authors' own PRISM benchmark and their own
  system — an in-house benchmark created by the same team that built the winning
  system is a conflict-of-interest risk common in benchmark papers; independent
  replication was not found in this search.
- Scope is limited to mechanical IoC extraction (indicators like IPs/domains/hashes),
  not higher-level CTI reasoning (TTP mapping, attribution, narrative report
  generation) — do not generalize these results to those other CTI tasks.

### New and load-bearing: the 97.6% is a CLASSIFICATION score over a regex-extracted candidate set

Verbatim: "We assume a total of 1,789 candidate indicators, extracted using IoC Searcher, a
state-of-the-art rule-based tool"; "For this purpose, we adopted IoC Searcher, a regular
expression-based tool proposed by Caballero et al., and integrated it into our pipeline";
"As discussed in Section 2.3, IoC Searcher demonstrates high recall across various IoC types,

extracted indicators"; Figure 9's caption: "Comparison of the F1 Score of the LANCE
implementation using GPT, Llama, Nvidia Nemotron, Gemini, and Gemma on **IoC

The LLM's job is to *label* indicators a regex has already found (IoC vs nonIoC) over an
enumerated candidate list. src-0007's 0.8240–0.8846 is precision on IoCs a model generates
itself from an article. This is a difference in **task format**, not only in scaffolding, and
unlike the "Vanilla LLMs" caption reading (weakened at cycle 21) it is stated by the paper
rather than inferred. Bears directly on `ctr-0001`'s SYSTEM confound.
