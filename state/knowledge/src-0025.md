## Summary

The primary artefact at the centre of the src-0004 incident, read for the first time at
cycle 72. Until now this base held only ENISA's **landing page** for this report
(src-0009, collected cycle 12, re-verified at cycles 16, 34 and 56). This entry is the
**corrected PDF itself** — v1.2, issued 09 January 2026 against an original publication
date of 1 October 2025.

Its value is that it converts the "no AI disclosure anywhere" claim from a statement about
a web page into a statement about the publication. It also surfaces one entirely new lead
(an internal `LOG HISTORY` section) and disambiguates which of the two ENISA reports
src-0004's 26-of-492 figure describes.

## Access constraint — read this before spending a fetch

A direct `WebFetch` of this URL returns **raw PDF object code and JPEG binary**, not text.
The local `Read` tool **cannot render PDFs in this environment** (`pdftoppm` /
poppler-utils is not installed), and the Bash tool refuses paths outside the repo, so the
saved binary cannot be post-processed locally either. Cycle 72 recovered the text by
prefixing the URL with the `r.jina.ai` extraction proxy. Three fetches were lost
establishing this.

The URL stored in the front matter is the **direct ENISA URL**, and it resolves
(HTTP 200, 4.3 MB) — the proxy is an access method, not the source.

## Key claims

1. **No AI disclosure in the front matter or in sections 1–7.** Asked directly whether any
   part mentions AI, artificial intelligence, generative AI, LLM or large language model
   *in connection with how this report was written, edited or produced* — as distinct from
   AI as a threat topic being analysed — the render answered **ABSENT**.
2. **The Legal Notice**, pulled whole (see *Relevant quotes*). Its seventh sentence
   disclaims responsibility for the content of referenced external websites — the same
   artefact class as the broken and fabricated footnote links.
3. **The document contains a section titled `LOG HISTORY`, listed as section 13**, whose
   contents no cycle has read.
4. **The footnote numbering reaches at least 237** at the truncation point, partway
   through Section 7 of 13; that footnote's text is
   `https://www.broadcom.com/support/security-center/protection-bulletin/lockbit-4-0-ransomware`.
5. **The Acknowledgements**, pulled whole (see *Relevant quotes*).

## Limitations of this source

- **The ABSENT in key claim 1 is PARTIAL and must not be flattened.** The render
  self-reported **TRUNCATED** mid-Section 7 of 13. Under methodological rule (xvi) the
  absence is valid for the **front matter and sections 1–7 only**, *not* for the whole
  document. **No cycle may upgrade it to a whole-document absence without reading sections
  8–13.** It does discharge the specific gap `institutional-incident-real-world-impact`
  open_questions[1] has carried since cycle 12, which named the front matter and legal
  notice.
- **The Legal Notice clause must not be read as a response to the incident.** A materially
  identical clause appears in src-0027, the **pre-correction v1.1** of the sister report,
  so it is standing boilerplate that predates the correction.
- **237 is a number seen at a truncation point, not a total.** It makes src-0004's 492
  figure *plausible* for this report and — together with the 149-footnote count of the
  sister report (src-0026) — identifies **this** report as the one src-0004's unattributed
  26-of-492 figure must describe. That is a **plausibility check and a disambiguation, not
  corroboration**. No cycle may write that 492 has been confirmed. 492 has still never
  been counted by anyone inside this base.
- **The Acknowledgements name an extensive review and validation network which did not
  prevent the defect** — but the section names no citation-checking or link-verification
  step, and **no cycle may infer from its silence that no such step exists**.
- Single render, single URL form, single date. Per rule (v) none of the above has been
  confirmed on an independent second form.

## Undone, and named precisely

**Read section 13, `LOG HISTORY`.** It is the natural location for a version changelog and
is the single most specific undone route on `institutional-incident-real-world-impact`. It
would also settle whether the whole-document AI absence holds. The obstacle is render
truncation, so it needs either a proxy that returns the tail of a 4.3 MB PDF or a
page-ranged extraction.
